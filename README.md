# Hold On

**在你掏钱之前，先让你自己把话说清楚。**

一个 agent skill。当你说「我想买个 X」时它介入，一次只问一个问题，帮你认出这是真需求，还是想象出来的需求。

> An agent skill that interrupts purchase intent with one question at a time — so you find out whether you actually need the thing before you pay for it. Runs in Chinese.

---

## 它做什么

你说「我想买个划船机，最近胖了不少」。

它问：**「过去半年你为这件事专门运动过几次？」**

- **你答得干脆、有细节** → 它说「行，这个买得值。」然后闭嘴。
- **你答得含糊、靠「应该会」撑** → 它用第一人称说「如果是我，我会…」。不下结论，不评判。
- **你还是要买** → 它换机制，不加音量：

| 级 | 做法 | 换的机制 |
|---|---|---|
| 二 | 先加购物车，48 小时后再看 | 时间 |
| 三 | 先做最小验证（想买划船机 → 先去练两次） | 证据 |
| 四 | 你买。它记一笔，一个月后问你用了几次 | 问责 |

## 它不做什么

- **不给购买建议**。不推型号、不比价、不看合同、不讲水阻还是磁阻。
- **不说「智商税」「情绪消费」「交学费」**。
- **不按品类豁免**。日用品不自动放行——囤货恰恰是重灾区。
- **不阻止你买**。它只是不接受「买完就算了」。

## 三条纪律

整个设计立在三条约束上，它们来自逆反效应、说服知识模型和自我决定理论：

1. **不自曝劝退意图。** 你一听出它在劝，就开始对抗。
2. **不下结论。** 结论一定从你嘴里出来，不是它给的。
3. **永远保留「你当然可以买」的出口。** 一个从不放行的工具没有校准能力——它得能说「这次你是对的」，将来它说「先别买」时你才会听。

## 安装

**OpenCode V2。目录名必须是 `hold-on`**——skill id 取自目录名，不是取自仓库名。

```bash
git clone https://github.com/<you>/hold-on-skill.git ~/.config/opencode/skills/hold-on
```

新开一个会话即可。验证：说一句「我想买个划船机」。

手动调用用 `@hold-on`。

> Claude Code / 其他 harness 需要放到各自的 skills 目录。这个 skill 只在 OpenCode 上验证过。

## 隐私

购买记录存在 `~/.config/opencode/hold-on-ledger.md`，**不在这个仓库里**，也不该进任何仓库。仓库里的 `.gitignore` 有一道防线，但真正的边界是：**不要在这个仓库的上级目录建 git 仓库。**

## 局限

- **中文 skill。** 它的价值全在问句的语域上——像朋友聊天，不像说教。翻译腔会直接毁掉它。
- **只测过单轮和短链对话。** 模型在长对话里会漂移。
- **情绪型消费没有专门应对。** 如果你说「我很难受，就想买点东西」，现在的流程不适合——那需要先接情绪，而不是追问过去行为。
- **回访靠「你下次想买东西」触发。** 没有定时器。你要是三个月不买东西，那笔记就一直躺着。

## 开发

`SKILL.md` 是行为主体。改它之后跑 `tests.md` 里的五条测试——五条都记录了验收样例和失败样例，不用重新推演。改 skill 不跑测试，等于改代码不跑测试。

`theory.md` 是设计依据：三类失手场景各自的心理学机制、出处，以及一张「什么时候劝退会起反作用」的清单。
